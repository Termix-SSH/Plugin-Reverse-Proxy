## Overview

Reverse Proxy shares services on your hosts through your Termix server. Routes belong to hosts and are managed from each host, and the plugin does the listening, certificates and forwarding.

Read the [docs](https://docs.termix.site/plugins/reverse-proxy) to set it up and use it.

<br />

## Features

- TCP, UDP, HTTP and HTTPS routes declared on each host
- Free Let's Encrypt certificates that renew on their own, plus self-signed and uploaded certificates
- Optional Termix login in front of any web route
- WebSocket support, forced HTTPS, custom headers and IP allow and block lists
- One overview of every route, its status and its certificate

## Support

Bugs and ideas for Reverse Proxy go in this repo: [report a bug](https://github.com/Termix-SSH/Plugin-Reverse-Proxy/issues/new?template=bug_report.yml) or [request a feature](https://github.com/Termix-SSH/Plugin-Reverse-Proxy/issues/new?template=feature_request.yml). Report an issue on the plugin's page in the Plugins tab fills in your versions for you.

Problems with Termix itself (login, hosts, credentials, sharing, sync) go in the [Termix repo](https://github.com/Termix-SSH/Termix/issues/new/choose). Not sure where it goes? Open it there and it will be moved.

Add as much detail as you can, in English if possible. For questions, join the [Discord](https://discord.gg/jVQGdvHDrf) server.
